# Authenticator — phase one

FEAT-0014 / BUG-0009 / DEV-0023. Software checks and physical acceptance are
separate: [verification](VERIFICATION_REPORT.md), [pending HWT-0015](HARDWARE_TEST_LOG.md),
[resource impact](performance/AUTHENTICATOR_RESOURCE_IMPACT.md).

## Operation

1. Settings > Security: configure your own 4–8 digit PIN. Fresh installations
   have no shared default PIN. Enable/unlock PIN before using 2FA.
2. Open 2FA > ADD > TYPE ON DEVICE; enter a name > NEXT; enter the masked Base32 secret > SAVE.
   Saving commits before success; failed saves retain prior records and permit retry.
3. The shared keyboard has a 1234567890 number row and standard QWERTY rows,
   Shift, symbols, Delete and Space. Base32 entry accepts only A–Z/2–7;
   account names support printable ASCII (23 characters maximum).
   Manual entry initially uses SHA-1 / 6 digits / 30 seconds; at most 8 accounts,
   32 decoded secret bytes each. ADD also offers USB/Wi-Fi paste using the
   [local account setup helper](ACCOUNT_SETUP.md); no QR camera, export, HOTP or
   password-manager app is added.
4. Arrows/swipes/short BOOT browse accounts. DELETE needs a separate confirmation
   contact after 350 ms. Back cancels editor/confirmation, then returns Home.
5. Connect through Wi-Fi Hub for NTP. Invalid Unix time displays dashes and
   prevents sending; uptime is never substituted. A pending code is canceled
   if time becomes invalid before the next USB transport tick.
6. Exit, lock and display sleep wipe plaintext accounts/editor buffers and
   cancel typing. Re-enter after PIN unlock to decrypt saved accounts.

Use public test accounts until physical acceptance. Keep recovery codes elsewhere:
there is no backup/export facility yet.

## Storage and PIN boundaries

`nibru_totp/vault`: one atomic NVS blob, at most 696 B. Header `NT`, version 1,
count is authenticated as GCM AAD; followed by 12-byte IV, 16-byte tag and
encrypted 83-byte fixed account records. Exact lengths, version, authentication
and account fields are checked before publishing plaintext. No demo seeds or
token logging remain. Corrupt/future/unreadable data is not overwritten by an
empty fallback; Back and re-enter retries loading.

Legacy `cnt` (NVS U8)/`iv`/`tag`/`data` records are read with the original key;
the next successful edit writes v1. Invalid loads and failed writes preserve
old records. Credential metadata uses one atomic 51-byte v1 blob in
`nibru_sec/credentials`; valid old salt/hash records remain readable. Legacy
plaintext PIN is deleted only after successful migration.

The vault key still depends on PIN/salt (PBKDF2-HMAC-SHA256, 2,048 iterations,
separate vault salt). Changing/disabling PIN is blocked while any TOTP storage
exists, including unreadable records. Deleting the final account explicitly
clears only `nibru_totp`, allowing credential changes. Do not delete your only
seed to change PIN. Safe key rewrapping/backup is deferred as BUG-0010.

This is not security certification. Short PIN/offline guessing, firmware
replacement and physical access remain limitations. Secure boot and flash
encryption are not enabled by this change.

## USB builds and completion

Default `lilygo-t-display-s3` keeps Serial/JTAG `ARDUINO_USB_MODE=1` and reports
keyboard unavailable, avoiding competing TinyUSB ownership of the same PHY.
Optional `lilygo-t-display-s3-hid` uses mode 0, TinyUSB keyboard plus CDC:

```powershell
pio run -e lilygo-t-display-s3-hid
```

This builds without uploading. HID is compile-tested, not physically accepted.
No GPIO reassignment: USB remains reserved GPIO19/20. Verify enumeration, data
cable, CDC/monitor behavior, host focus and US keyboard layout on hardware.

Transfers allow 64 ASCII characters or 6–8 numeric digits for codes, one
press/release per 15 ms scheduling interval. Native transport directly queues
TinyUSB reports instead of synchronous Arduino SendReport; endpoint readiness
must return after final release before success. Busy endpoint bound: 500 ms.
Observed unmount/suspend aborts; canceled key-downs retain a deferred release
until endpoint readiness returns. Observed disconnects never resume queued digits.
No automatic Enter is sent. `HID reports sent` means transport completion,
not that the intended host field received text. Extremely short unobserved
connection changes and actual delivery remain hardware acceptance cases.

## Simulator and resource limits

Windows adapters use real CNG SHA/HMAC/PBKDF2/AES-GCM and OS random bytes. This
tests shared algorithms/records, not ESP32 mbedTLS acceleration or entropy/timing.
Other hosts retain explicitly synthetic crypto doubles; RFC vectors run with
the real Windows backend. Older simulator records generated by synthetic crypto
are not real encrypted-vault migration fixtures; preserve for inspection.

Desktop saves use checked temporary-file replacement and in-memory rollback on
OS errors. Loads bound counts/lengths and write-protect corrupt files. Simulator
reboot reloads from disk. Tests isolate `.testbuild/auth_runtime_test` and
`.testbuild/auth_runtime`; normal runtime and tracked fixture are preserved.
`--runtime-dir=...` selects an isolated simulator store.

Without Windows CMake/MSVC, `tools/run_desktop_tests.bat` falls back to the Python
runner, using CXX/SDL2_ROOT or ignored local tools. It never downloads/installs
dependencies. Normal CMake builds link bcrypt on Windows; embedded dependencies
remain unchanged. Runtime heap/PSRAM/stack/latency/power are NOT MEASURED; follow
[profiling scenarios A–E](MEMORY_PROFILING.md), including >=20 physical cycles and
>=150 KiB free internal byte-addressable heap acceptance.
