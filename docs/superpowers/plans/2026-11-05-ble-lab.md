# BLE Lab implementation plan

The owner selected multiple fictional BLE devices visible in a scanner for classroom demonstrations. Simulator work is paused.

- Reuse the checked Bluedroid startup path used by the keyboard. Keep radio ownership exclusive and enable existing Wi-Fi modem-sleep coexistence while BLE is active.
- Add an asynchronous non-connectable advertiser with stable random addresses and LabBLE01 through LabBLE10 names. Use a custom 128-bit service UUID for scanner filtering. Default to five identities and thirty seconds, adjustable from one to ten identities and five to sixty seconds.
- Rotate addresses and payloads after advertising stops. Wait for GAP completion events, fail on rejected operations or a two-second timeout, and retain radio ownership if teardown fails. No controller reinitialization while rotating identities.
- Add a physical Home app, stop on Back, timeout, lock and sleep, and cover packet contents, state progression, failure cleanup and twenty host cycles. Run the host suite and the actual ESP32 build and resource check. Do not edit, register or run the desktop simulator.
- Increment to v0.17.0, append engineering evidence and identify physical receiver/resource measurements as pending.
